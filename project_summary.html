1. 연구 개요

목표: UAM(도심 항공 모빌리티) 수직 착륙 시 발생하는 VRS(Vortex Ring State) 현상을 강화학습으로 회피하며 안전하게 착륙하는 제어 정책 학습.

투고 논문: APISAT 2027 (2026.07.31 제출) — "VRS-Safe UAM Landing Control via Reinforcement Learning with Ontology-Guided State Classification"

사용 알고리즘: SAC (Soft Actor-Critic), auto_alpha=False, alpha=0.03, deterministic=True (평가 시)

핵심 구성요소 3가지:

  • VRS-aware Reward Shaping — CAUTION 구역 접근 시 점진적 페널티
  • 온톨로지(Ontology) — DANGER/RECOVER 진입 시 즉각 최대 추력 오버라이드 (rule-based)
  • Context DB — 사람이 마킹한 CAUTION 경계 상태 1,084개 저장, 에이전트가 근접 시 보너스 +3.0 (CAUTION 구역에서만)

추가 시도: PINN(Physics-Informed Neural Network) 기반 Dyna-style 데이터 증강 — n=3 가상 샘플/실제 스텝

2. VRS 환경 정의 (uam_vrs_env.py)
VRS 상태 구분 (Vz/Vh 기준)
상태조건 (Vz/Vh)처리 방식
SAFE< 0.5정상 비행
CAUTION0.5 ~ 0.8점진적 페널티 + Context DB 보너스 적용 구간
DANGER0.8 ~ 2.0온톨로지: 즉각 최대 추력 오버라이드
RECOVER≥ 2.0온톨로지: 즉각 최대 추력 오버라이드

SAC 입력 (state): [V_x, V_z, alt, T_norm] — 4차원. Context DB는 reward에만 영향, SAC 입력 불포함.

베이스라인 환경: NoVRSEnv (uam_baseline_novrs.py) — VRS 페널티·온톨로지 없음, 착지 성공/실패 보상만.

커리큘럼 3단계:

  • Stage 1: 고도 20–40 m, max_steps=6,000 (15초)
  • Stage 2: 고도 60–90 m, max_steps=10,000 (25초)
  • Stage 3: 고도 100–150 m, max_steps=16,000 (40초)

4. PINN 구조 및 Loss (uam_pinn_model.py)

구조: 4-layer feedforward, Tanh 활성화, 잔차 예측 (next_state = state + Δ)

입력: 5D (Vx, Vz, alt, T_norm, dT) → 출력: 4D (다음 상태 변화량)

L_PINN = L_data + λ · L_phys L_data = MSE( f_θ(s,a), s'_obs ) # 실제 전이 데이터 fitting L_phys = MSE( f_θ(s,a), φ_RK4(s,a) ) # RK4 물리 방정식과의 일치 λ = 1.0, RK4 적분 dt = 1/400s

Dyna-style 증강: PINN이 s'만 생성 → env reward function이 r 계산 → (s, a, r, s') 리플레이 버퍼 추가. n_imagined=3/실제 스텝.

원인: CAUTION 구역(Vz/Vh=0.5~0.8) = VRS 경계 그 자체. 이 구역에 보너스를 주면 에이전트가 VRS 경계 근처를 맴도는 행동을 학습함 → Stage1에는 Context DB 부적합, Stage2+(희소 학습 신호 구간)에서만 유효.
베이스라인 ep400 vs ep1000 선택 이유

ep1000(baseline_final)은 VRS를 통과해서 착륙하는 방법을 학습 → 착륙 성공률 69.5%, VRS 38.1%. 이는 "VRS를 통과해도 착륙 가능"을 보여주지만, VRS 안전성 지표가 전혀 없는 결과. 논문 서사(VRS 회피 능력 부재)에 맞는 ep400 사용.

6. APISAT 2027 논문 수정 이력
  • Section 4.1 — CartPole → UAM 전환 이유 추가 (SAC 파이프라인 검증 후 UAM 환경 적용)
  • Section 4.2 문단 추가 ① — 0.9% VRS 진입률은 per-step 기준, 온톨로지 즉각 오버라이드로 일시적 교란에 그침 (vs 베이스라인 15.3%)
  • Section 4.2 문단 추가 ② — 59.0% 착륙 성공률은 보수적 하한값 (VRS=near-terminal 처리 때문), Section 4.4로 연결
  • Section 4.2 문단 추가 ③ — Stage1(20–40m)이 ground-induced upwash, 건물 후류, 선행기체 하강류가 집중되는 공력학적 최악 구간임을 명시
  • Section 4.4 신설 — Limitations and Future Work: VRS avoidance(현재) vs VRS recovery(향후) 두 sub-problem 분리, 난기류 유추로 VRS의 회복 가능성 제시
  • PINN Loss function — 교수님 지적 반영, L_PINN = L_data + λ·L_phys 수식 및 RK4 물리 제약 명시
  • Figure 4 — 베이스라인 vs 제안 방법 막대 그래프 (uam_comparison_figure.py로 생성)
논문 내 제안 방법 표기: "SAC + VRS-aware Reward + Ontology". Context DB는 Stage2 결과에서 별도 언급. 59.0%/0.9% 수치의 실제 소스는 fresh_best.pth (Context DB 없음).
7. 향후 연구 방향 (교수님 피드백 기반)

전제: 착륙은 무조건 100% 성공 — VRS 진입 여부와 무관하게 UAM은 반드시 착륙. 핵심 지표는 "얼마나 안전하게 착륙하는가".

VRS 재정의: 현재 VRS = near-terminal 실패 처리 → 향후 VRS = 난기류(turbulence)처럼 회복 가능한 외란으로 모델링.

방법론설명목표
방법론 0 (비교군)단순 PID 제어 또는 VRS 고려 없는 순수 RL착륙은 하지만 안전 지표 부재
방법론 1 (Recovery)VRS 진입 허용, 추력 증가 + 수평속도 조절로 탈출 후 착륙VRS 체류 시간 최소화, 회복 성공률 최대화
방법론 2 (Avoidance)하강 경로를 VRS 위험 구역 밖으로 유지VRS 진입률 0%, 안전 마진 확보 (현재 연구)
방법론 3 (통합)회피 우선 + 진입 시 회복 정책 전환착륙 100% + VRS 안전성 동시 최적화

고정 시나리오: 단일 하강 궤적을 픽스한 상태에서 방법론 0~3을 동일 조건에 적용 → 공정 비교. VRS 진입 횟수, 체류 시간, 착륙 정밀도 지표 구분.
